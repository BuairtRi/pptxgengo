# PowerPoint browsing libraries

Two generated documents let colleagues browse and copy slides without using the
CLI. They contain native PowerPoint shapes and text, not screenshots of pages.
Actual PowerPoint visual acceptance and copy/paste qualification remain separate
from structural generation.

## Commands

```sh
pptxgengo design browsing-library --kind templates --bundle v11 \
  --as-of 2026-10-07 --out NEW-TEMPLATE-DIRECTORY
pptxgengo design browsing-library --kind reusable --bundle v11 \
  --as-of 2026-10-07 --finished-library PRIVATE-REVISION-ROOT \
  --out NEW-REUSABLE-DIRECTORY
```

The equivalent `pptxdesign browsing-library` command is available. The date is
mandatory: it controls recorded freshness and the legal year, rather than silently
changing eligibility according to a developer workstation clock. Outputs must be
new. Generation fails rather than publishing a partial deck when any required
entry cannot bind, render, resolve a pinned asset or fit its declared geometry.

The template deck includes a “How to use this deck” page, family dividers, native
PowerPoint sections, every retained catalog template variant, and an independent
frame/rail chapter. Deprecated templates remain available behind visible warning
pages. The default `--frames catalog` includes every catalog-defined rail/footer/split
variant (36 in the current V11), with all 649 retained template variants.
This produces 717 pages rather than multiplying every presentation setting.
Each template keeps its canonical pinned source frame. The independent frame
chapter uses each catalog entity's declared default request: light/inverse
surfaces, one title line, no source lines, standard density and a visible header;
navigation rails have two illustrative tabs. It includes 12 nonsplit variants
(four rail choices times three footers) and 24 split variants (two valid rail
choices times three footers times four splits). These defaults are recorded in
each frame's coverage entry.
`--frames exhaustive` independently covers every valid combination of rail, footer,
split, surface, rail
surface, title allocation, source allocation, standard/appendix density,
header visibility and navigation tab counts. The coverage manifest records each
rendered template/frame and each candidate structurally rejected by the resolver.
Semantically identical hidden-header requests share a rendered page with explicit
manifest aliases; every alias is checked against resolved geometry and the actual
renderer. The coverage mode is explicit in the manifest. A rendering or fitting failure is never converted into an exclusion. Independent
frame examples do not claim that arbitrary templates work in arbitrary frames.

The reusable deck includes **latest approved revisions only**. A newer draft
leaves the last approval eligible. A newer deprecation withdraws earlier approvals.
An expired latest approval does not resurrect an older approval. The complete
immutable library is verified before selection; tampered or duplicate revisions
fail generation. Visible metadata pages and content-slide notes retain identities,
revision digests, steward, approval date, scope, expiry and destination review
requirements. Approved content is compiled unchanged, with independent identities
for the browsing deck. CI records its current compiler separately from the
original revision's compiler; regenerated bytes are not described as the original
approved rendering or as desktop-qualified output.

## Private CI input contract

Every future tag-driven installation archive, both `cli-only` and `full`, requires
both browsing decks. This does not modify existing v4.1.0 release artifacts.

Configure protected GitLab release variables:

| Variable | Input |
| --- | --- |
| `WMDS_BRANDING_ARCHIVE_URL` | Private HTTPS tar.gz, rooted at the registered branding paths |
| `WMDS_BRANDING_ARCHIVE_SHA256` | Exact SHA-256 of that immutable archive |
| `WMDS_FINISHED_LIBRARY_ARCHIVE_URL` | Private HTTPS tar.gz containing closed immutable authored slide revision directories |
| `WMDS_FINISHED_LIBRARY_ARCHIVE_SHA256` | Exact SHA-256 of that immutable archive |
| `WMDS_BROWSING_FRAMES` | `catalog` (default) or `exhaustive`; recorded in the deck coverage |
| `WMDS_BROWSING_AS_OF` | UTC pipeline creation date, `YYYY-MM-DD` (automatic default; overrides must match) |

The URLs can be masked presigned private S3 URLs or Generic Packages in this
private GitLab project. The job sends its token only to the exact project package
endpoint and does not follow redirects. Safe extraction rejects paths, links and
nonregular entries. Registered branding assets must match their source pins;
finished revisions must match their complete inventories and template pins.

`release:resources` regenerates the two decks from the tagged source. It fails
with an actionable missing-input error if private branding or actual approved
content has not been supplied. Synthetic source specimens are never substituted
for the reusable-slide library, and CI never grants approval. Date-bound authored
content from another year requires review and republishing, rather than silently
rewriting its legal year.

All six platform installation archives contain:

```text
browsing/
  template-library.pptx
  template-library.manifest.json
  reusable-slides.pptx
  reusable-slides.manifest.json
browsing-manifest.json
```

Archive assembly requires both actual deck files and both coverage manifests and
checks their exact hashes before including them. They are part of the final
archive checksum, SBOM/security scan and signed release manifest. `full` packages
also retain the authoring bundle, originals, gallery, documentation and skills.
All CLI CI runs in private GitLab. Generated branded presentations and private
authored content stay in its private release artifacts.

## Qualification evidence

The current exhaustive frame corpus generated all 9,072 distinct editable frame
pages plus its guide in 52.82 seconds: 64,396,000 actual PPTX bytes. All 51,840
candidates were accounted for: 9,072 rendered pages, 2,592 hidden-header equivalent
aliases and 40,176 structural rejections. This is geometry/generation evidence,
not PowerPoint visual/copy-paste acceptance. Every alias preserves resolved visible
geometry; an actual renderer comparison also preserved editable text/shapes.
All 649 current catalog templates bind successfully, including retained deprecated
entries. Complete branded template rendering still requires the registered private
branding originals. Real approved reusable content has not been supplied; generic
fixtures exercise selection and native generation without claiming content approval.

## Installation integrity

Legacy v4.1.0 CLI packages remain supported. Browsing-inclusive packages require
both PPTX documents, both typed coverage manifests and the exact five-file
browsing inventory. Activation, repair and rollback use the installer package
verifier, including the complete browsing hashes and manifests. Unlisted CLI
files remain rejected. Release assembly uses the same artifact verifier.
Both decks must agree with the top inventory's exact bundle, source revision,
source commit, compiler, release identity, freshness date and immutable private
input archive hashes. Their recorded pipeline time must have that UTC date.
CI additionally compares the inventory with protected input hashes and its
authoritative pipeline time and commit; independently coherent documents from
different releases cannot be combined into an installation archive.

The verifier follows the actual presentation slide order and internal
relationships, verifies native slide identities against the serialized whole-page
inventory (including guides, dividers and notices), and rejects missing,
duplicate, external or orphan slide parts. Source/bundle/font/asset pins, exact
catalog counts, frame candidate/alias/exclusion accounting and immutable approved
revision selection are checked. Bounds are 16 MiB for coverage metadata, 512 MiB
for PPTX archives, 100,000 members, 64 MiB per member, 4 GiB total uncompressed,
8 MiB per inspected XML document and 20,000 actual presentation slides. The
current exhaustive developer matrix fits those bounds; ordinary installation
archives default to the convenient 717-page catalog deck.

These checks prove integrity and metadata coherence. Verify the private signed
release manifest before trusting the archive. They do not replace publisher
signature verification, an operator's content approval or native PowerPoint
visual/copy-paste acceptance.
