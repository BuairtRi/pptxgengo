# Reviewed native text reconciliation

This source capability follows [native field mappings](native-field-mapping.md)
and [generation/shape lineage](native-lineage.md). Stable **v4.1.0 predates it**.
The Mac synthetic Save As/three-text-field/reorder workflow has passed native
UI and independent supplied-file checks; see [retained evidence](native-roundtrip.md).
Windows desktop execution and broader editing acceptance remain pending.
Headless package mutations alone do not establish PowerPoint acceptance.

## Preserve and propose

Keep the original `builds/<build-id>/` immutable. Edit a separate PowerPoint copy.
Use a baseline generated by a build with lineage tags and exact field mappings:

```sh
pptxgengo design project reconcile propose --project ./deck \
  --edited './colleague edited.pptx' --out ./new-text-review
```

The default baseline is the current build and receipt hash pinned in project
state. For an older build, provide both `--build BUILD_ID` and
`--receipt-sha256 TRUSTED_RECEIPT_SHA256`. Obtain the trusted hash from the
original retained state or an independently preserved record; computing a new
hash of a modified receipt does not restore its authenticity. The baseline must
match the current exact toolchain lock. Older builds without lineage require a
new build and a new editing copy.

The new directory contains a closed manifest, `report.json`, the edited PPTX,
receipt-verified baseline inputs, and the current authored source tree. Existing
destinations are refused. Creating a packet changes neither source nor build
state. Standard output names the packet, `report_sha256` and full report.

Read each field's stable slide/source-slot identity, baseline, current YAML and
edited native copy. Statuses are:

| Status | Meaning |
| --- | --- |
| `no_op` | Both copies match the baseline. |
| `yaml_only` | Source changed; native copy still matches the baseline. |
| `matching_changes` | YAML and native text made the same change. |
| `native_only` | Only native text changed; a supported proposal. |
| `conflict` | YAML and native copy differ from each other and the baseline. |
| `manual_review` | Correspondence or native content is unsupported. |

Only unique named plain string fields are selectable. Matching uses generation,
slide and shape tokens with keyed source slots. Slide position, object name,
physical numeric ID, current copy and geometry do not identify source fields.
Exact paragraph/hard-break text is preserved; mixed rich runs, bullets, dynamic
fields, table cells and ambiguous mappings require manual review. Missing or
duplicated objects never imply a deletion or guessed update.

`manual_review` also lists geometry, format, grouping, added/deleted/unmatched
objects, and changed payloads outside named text (including notes, media and
master parts). Serialization changes can produce conservative review items.
A text proposal does not mean the edited deck is fully reproduced by YAML.

## Decide and adopt

Write a separate YAML or JSON decisions file. Copy the exact packet report hash
and actual proposal IDs; name the reviewer and reason for each decision:

```yaml
schema: pptxgengo.text-review-decisions.v1
report_sha256: <report_sha256 from propose>
actor: <actual reviewer>
decisions:
  - field_id: <native_only or conflict field ID from report.json>
    action: use_native
    reason: <why this copy is accepted>
  - field_id: <another supported proposal ID>
    action: keep_yaml
    reason: <why current authored copy is retained>
```

Decisions are explicit review records. Claims, commitments and ambiguous meaning
still require the project's actual copy/evidence review. Omitted proposals stay
pending. Unknown fields, duplicate decisions, wrong report hashes and unsupported
proposal selections are refused.

```sh
pptxgengo design project reconcile adopt --project ./deck \
  --packet ./new-text-review --decisions ./review-decisions.yaml
pptxgengo design project build --project ./deck
```

Adoption verifies packet closure, reloads the receipt-pinned baseline, reconstructs
the reviewed source snapshot and replays the entire comparison. Recomputing the
packet manifest cannot authorize a forged proposal. Any source change after
packet creation requires a fresh packet and review. Parallel YAML edits present
when the packet was created remain visible as conflicts and are retained in
predecessor source snapshots if explicitly replaced.

Selected scalar edits preserve comments and split source representation; untouched
source files are not rewritten. Project validation and changed-slide fit checks
must pass before the guarded mutation. `--bundle PATH` and `--engine NAME` can
select the exact locked runtime when it is not installed at the default path.
Shared definitions, build baselines and the hand-edited deck stay immutable.

The adoption receipt records actor, time, input hashes, before/after source hashes,
old/new field copy, remaining proposals and **all manual review items**. Exact
edited deck, report and raw decisions are retained under
`decisions/reconciliations/<adoption-id>/`; receipt and predecessor source history
are retained in `decisions/`. Repeating the same packet and exact decisions bytes
returns the same receipt without another mutation while the adopted source and
retained inputs remain unchanged. Empty decisions create no source or receipt
write. A newly proposed packet recognizes matching adopted text as no new change.

Build a new generation, render and visually review the changed pages against the
edited copy. Adoption does not grant native review, operator acceptance or full
synchronization. Geometry, new slides, chart/table edits and notes adoption remain
separately scoped work.

## Evidence and limits

Generated-package fixtures cover three independent text changes, rebuild text,
parallel conflicts, no-op and repeated adoption, split readable copy/comments,
closed packet integrity, forged reports, source drift, immutable baseline guards,
and preservation of unsupported package changes in adoption receipts. CLI tests
exercise propose/adopt/repeat with paths containing spaces and bounded inputs.
These tests simulate package mutations. An actual colleague editing three fields,
Save As, slide reordering and normal text editing still need qualification in
Mac and Windows desktop PowerPoint.
