# Cycle composition implementation scope

The first process-family slice targets existing typed `wmds/component/cycle`
components. It does not implement a general flowchart graph, branch/join topology,
forked-roadmap composer, or automatic semantic inference from native positions.

The composer inspects resolved arguments, converts positional `active` and
feedback `from`/`to` into stable keyed entities, applies strict declarative edits,
then projects keys back into renderer indices. Local template array overlays
retain the same step/loop identities through reordering. Existing source ordinal
keys use `source-NNN`; explicit overlays retain their supplied identities. The
frozen source cycle renderer and its original contract are unchanged.

Explicit materialization is required for bound arguments. The shared composition
transaction checks source preimages, immutable frame/grid/provenance, local
ownership, absence of native overrides, measured frame fit and all authored files
before apply. Center context and optional copy/styling belong to complete entity
replacement, rather than implicit patch merging. Stage removal refuses dependent
loops/current markers unless an explicit cascade removes them, or earlier
operations resolve the dependencies. Whole-candidate validation accepts 2–12
stages and no more than 32 loops, with known stable endpoints and no self-loop.

## Focused source evidence

`cycle_composition_test.go` derives a local fixture from the frozen catalog
`phase/define` source, retaining its typed cycle controls while widening the
component allocation for the composition exercise. Source tests cover a
four-to-five-to-three stage composition, new feedback loop, preserved current
stage through reorder, mapped renderer indices, guarded preview immutability,
apply/decision/stale hash, build, explicit cascade, missing/self endpoints,
unknown fields and irrelevant authored zero/false/empty/null values, binding
ownership, label overflow and native override refusal. CLI tests reject ambiguous
flag combinations before filesystem access.

A focused metadata regression demonstrated that sequence comment matching
included YAML parser positions and nested comments in its identity. The shared
helper now compares semantic values and requires uniqueness in both sequences.
Tests cover preserved head/nested-label comments on unique unchanged step and
loop records during reorder, and avoid reattaching instance-specific comments to
duplicate values. This is not a complete Keys-overlay comment contract: a loop
whose positional endpoints change during step reordering is a changed renderer
record, so value matching alone does not establish its original comment identity.
Source predecessors retain the original authored bytes.

These checks establish source and measured-renderer behavior. They do not claim
actual macOS/Windows PowerPoint edits, native semantic adoption or every catalog
cycle/frame variant is qualified. Native qualification belongs to the root
integration exercise and should retain exact inputs/receipts rather than turn a
single specimen into a general guarantee.
