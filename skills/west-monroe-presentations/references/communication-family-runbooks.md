# Customize communication families by their job

Start with the intent of the slide and the supplied evidence. Templates provide
visual examples; their stock number of rows, cards, people and stages is not a
requirement. Inspect the actual local components and frame, then use the relevant
semantic command or [component](component-composition.md) and
[table](table-composition.md) operations. Use native paragraph lists where copy
needs normal editing. Build, inspect fit and review native output after changes.

| Family / communication job | What changes | Meaning to preserve and preferred workflow |
|---|---|---|
| Covers and navigation | Section labels, agenda counts, progress markers, closing action | Manage deck sections/navigation with project section; ensure index order agrees with the deck. Component edits change visible copy, not section membership. |
| Understanding | Ask, context, scope, assumptions, traceability | Keep requirements and evidence IDs explicit. Table rows can change; duplicate requests must not disappear in summarization. |
| Core content | Headings, card/list counts, quote length, key messages | Use component keyed body/list edits. Keep attribution and the headline's claim supported. Split copy that no longer fits. |
| Argument/frameworks | Pillars, trade-offs, from/to comparisons, hierarchy levels | Use keyed component collections or layers. Change labels and coupled descriptions together; reorder is not a new weighting or ranking. |
| Evidence | Measurements, units, datasets, series and source | Quantitative commands own chart meaning; table handles explicit observations. Preserve units, denominator and period. |
| Diagrams | Funnel/pyramid stage counts, conceptual sets | Component lists and keyed Venn members preserve conceptual relationships. Do not infer quantities from areas or geometry. |
| Heat maps | Capabilities, domains, missing observations, score labels | Assessment for ordinal scores; table for explicit cells/domains; quantitative for continuous measures. Zero and unassessed differ. |
| Status/steering/RAID | Risks, owners, actions, status definitions | Table preserves IDs, labels and metadata. Changing labels must not silently change canonical status color. Keep closed items' disposition explicit. |
| Venn | Set count, overlap memberships and labels | Component set/region adapter uses named members. Deleting a set explicitly removes incident regions; geometric overlap is not a membership import. |
| Architecture | Layers, nodes, containment and connectors | Diagram/layer commands own geometry and relationships; preserve framing bounds. Native movement does not establish containment or reporting. |
| Solution/process | Work, actor lanes, outcomes, joins, context | Process for work graphs; tables/cards for SIPOC, metrics, readiness and service context. Do not turn every diagram into a flow. |
| Lifecycle | Repeating stages, phases, outcomes, role matrices | Cycle for loops/current stage; component phases/current marker for linear phases; team/table for responsibility. |
| Software/intellio | Adoption scope, release phases, capability/readiness evidence | Process/portfolio/Gantt where applicable; content/table for stated capability and observed evidence. Do not infer product claims from a diagram. |
| Team curves | Capacity, roles, scope and demand assumptions | Staffing owns series, units and time/effort coordinates. Table/role content must agree with declared capacity assumptions. |
| Maturity curves | Stage definitions, current/target, inflection and branching scope | Maturity owns keyed stage coordinates and markers. Labels must distinguish scope from measured maturity; no automatic ordinal score import. |
| Stakeholders/teams | People, roles, pods, reporting, governance, decision rights | Team commands preserve membership and reporting. Person copy/photo changes do not imply a new organizational relation. |
| Modernization | Release waves, adoption scope, layers, ownership and outcomes | Process/portfolio/layer commands for structure, tables/cards for readiness and evidence. Change technical topology independently from organizational reporting. |
| Decision records | Options, criteria, rationale, decision owner and disposition | Table/component keyed criteria/option edits; preserve the explicit decision record and rejected options. Changing layout does not reopen or approve a decision. |
| Change management | Audiences, adoption actions, channel plans, feedback and readiness | Component/table for authored audiences/actions/evidence, process for handoffs, portfolio/Gantt for time. Keep communications facts distinct from measured adoption. |
| Investment and value | Assumptions, benefits, cost, scenarios and observations | Commercial calculations and quantitative charts own numeric meaning; source tables retain explicit facts. Distinguish projected from realized value, cash from returned capacity, and exact units/periods. |
| Approach | Activities, deliverables, phases, gates, ownership | Component phases and process for sequence; Gantt for periods/tasks; table for evidence and gate criteria. Dates remain explicitly authored. |
| Roadmaps | Horizons, initiatives, forks and time | Portfolio owns horizon membership/dependencies; journey owns current/chosen road markers; Gantt owns numeric schedules. Later is not a delivery promise. |
| One-page proposals | Ask, recommended scope, approach, value, terms and decision | Coordinate component cards/tables across the complete page; commercial commands own calculations. Do not silently turn benefit order into priority. |
| Credentials / about firm | Capabilities, practice counts, locations, leaders, sources | Component/table with supplied evidence. Avoid invented credentials or stale numeric claims; person/media assets require explicit provenance. |
| Commercials | Rates, fees, allocations, scenarios, terms | Commercial commands own assumptions/calculation/rounding. Table only changes explicit displayed facts; a displayed total is not recalculated automatically. |
| Case studies | Client context, intervention, outcomes, citations | Component copy/media and quantitative/table observations. Keep source attribution, permission and measured versus projected outcomes clear. |
| Research interviews | Participants, access, interview steps, observations | Table preserves identities and evidence references; component sequences show progression. Changing participant counts does not authorize changing quotations. |
| Workshops / sessions | Agenda steps, timing, activities, groups, outcomes | Component step/phase lists and tables; process for handoffs. Update duration/outcome captions explicitly when counts change. |
| Runbooks | Steps, owners, evidence, go/no-go, escalation and rollback | Native tables/checklists for procedures, process for decisions/handoffs, Gantt/timeaxis for explicit schedule facts. Keep rollback/exit criteria coupled to the correct step. |

Family tags overlap these jobs. The actual source type and intended meaning decide
the command. For any unsupported shape or formatting, retain the original native
package, use explicit source reconstruction and qualify it; never label an
arbitrary import or a source-only test as a desktop round-trip success.

## Companion copy and decorative surfaces

Inspect the complete template before adding text. Some workshop and content
layouts use an intentionally empty block as a colored backing, with its heading
in a separate companion text node. Edit the heading node's authored copy; adding
text to the empty backing can overlap that heading even if both individual boxes
pass measured fit. Preserve empty decorative copy unless the redesign explicitly
relocates the companion text and reviews the combined visual.
