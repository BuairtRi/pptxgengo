Implementation templates: summary

Six linked working documents that turn the definition path into decisions. Each one ends in Approve, Revise, Hold, or Stop.

IMPLEMENTATION TEMPLATES

01

Opportunity Brief

IDENTIFY   ·   Path steps 01–02

Frames a request or signal as an evidence-backed problem before any solution is chosen.
Owner: Product manager
Decision: Senior leader: is it worth defining?
Proposed pilot: Rules Engine, rebuilt from its PGB deck.

02

Product Brief

DEFINE   ·   Path step 03 (PRD)

Turns an approved opportunity into a product direction: outcome, experience, scope, and measures.
Owner: Product manager
Decision: Senior leader approves direction and measures.
Proposed pilot: Rules Engine, checked against its existing PRD.

03

Feature Brief

DEFINE → BUILD   ·   Path step 04

Defines one buildable, testable capability: stories, business rules, acceptance conditions, and tracking.
Owner: Product manager with Engineering lead
Decision: Product, Engineering, and QA or Design: ready to build.
Proposed pilot: Rules Engine, to define its first epic.

04

Technical Implementation Plan

BUILD   ·   Path steps 05–06

How Engineering delivers safely: architecture, data, environments, rollback, and human-reviewed AI assistance.
Owner: Engineering lead
Decision: Engineering and required reviewers: ready to execute.
Proposed pilot: Rules Engine tech spec, drafted with the Architecture Design Agent.

05

Testing, QA, and UAT Plan

DEFINE → RELEASE   ·   Runs alongside the path

Shows what was tested, where, with which data, and what remains uncertain, including user acceptance.
Owner: QA or engineering test lead; Product owns UAT
Decision: Test evidence supports release readiness.
Proposed pilot: Reconcile AI, ahead of its November MVP.

06

Initial Release and GTM Plan

DEFINE → OPTIMIZE   ·   Runs alongside the path

Defines the smallest valuable first release, its audience, readiness by function, and expansion rules.
Owner: Product manager with functional leads
Decision: Named decision-maker: Go, Revise, Hold, or Stop.
Proposed pilot: Reconcile AI, for its first release.

Linked by readable IDs:  OPPORTUNITY → PRODUCT → FEATURE → ACCEPTANCE → TEST → METRIC   ·   Proposed working templates and pilots, to validate with DXC.
