# Permanent Go authoring APIs after the semantic conversions

## Already available

- `library-find/inspect --summary`: unified SQLite, real source purpose/topology, named binding zones and hash-verified screenshot paths. `library-fit` compares explicitly supplied real-content candidates. Semantic recipe choice still needs judgment.
- `project scaffold`: actual shared-parent ancestry and measured component geometry, separate synthetic source values, explicit omitted-node receipts. `project detach/fork`: editable local compositions with frozen provenance.
- `project edit`: stable-ID template/value/brief-path changes, strict binding validation, atomic replacement, exact predecessor and decision receipt; comments, notes, hidden flags and sections are retained.
- `project measure`: saved renderer-report text intersections and panel-spill advisories. It does not certify native fit, recover source relationships or measure every chart/table internal label.
- `project section`: native group list/add/rename/remove. `project build/check/export`: strict runtime pins, original/derivative asset hashes, maintained state, offline runtime packaging.
- `pptxscene extract/build`: real source OOXML/dependency extraction and reconstruction. This is a low-level scene project, not an import into the maintained semantic deck schema. Its reconstruction removes source section lists; it must not be mistaken for the section-preserving semantic importer proposed below.

## Implement next: four reusable boundaries

| Boundary | Suggested Go API / CLI | Missing capability observed | Required safeguards |
|---|---|---|---|
| Source intake | `deckproject.InspectPresentation` / `project source inspect --source ORIGINAL.pptx --out NEW` | The conversions repeatedly extracted exact visible paragraphs, speaker notes, hidden flags, native section membership, image relationship/crop/rotation metadata, embedded exhibits and source hashes with private scripts. | Reuse `nativepkg`/OPC parsing. Emit a versioned source inventory and original asset registry, not guessed semantic layouts. Preserve exact runs/paragraphs as evidence and expose business-copy projections separately. Never rewrite the original. |
| Authored composition installation | `deckproject.InstallScaffold` or a transactional `project edit --scaffold FILE` extension | Scaffold output still requires hand-merging local templates, asset entries, parent snapshots and per-slide bindings. Isolated fragments were merged by ad hoc serializers. | Explicit stable IDs, collision rejection, genuine ancestry validation, complete values and finite schema checks; atomically update the project with predecessor/receipt. Keep original notes/hidden/sections. Do not silently import synthetic specimen values as supplied content. |
| Qualification evidence | `deckproject.CompareArtifacts` and `ImportNativeReview` / `project compare`, `project review import` | Each lane separately implemented ZIP-part comparisons, PNG hash carry, source/inspection hidden-slide equivalence and native acceptance chains. | Closed, named equivalence policies: for example only hidden flags and source-derived section UUID differences. Distinguish whole-byte identity from normalized equivalence. Require exact source/build/PPTX/PDF/PNG hashes and per-page decisions; reject unexplained differences. Native acceptance is never inferred from compilation or matching unreviewed files. |
| Minimal delivery export | `deckproject.DependencyClosure`, export selection options, `project delivery manifest` | Whole-tree maintainer exports included histories, helpers and earlier packages. Authors staged minimal project copies manually to create clear preferred/alternative deliverables and relocated no-Go proof. | Compute closure from source assets, locks, referenced context/briefs, snapshots, current state/build and qualified receipts. Explicit archive/include policy with receipts; preserve predecessor outputs. Generate one manifest naming preferred, meaningful alternatives and inspection-only files. Keep source evidence needed for maintenance even when not rendered. |

## Follow-on layout APIs

Expose the engine's real font measurement as `project measure --project` for editable allocations, line breaks, title lines and containing surfaces; today's report-only command cannot propose a truthful allocation before a strict build succeeds. Add explicit group transforms that move surfaces/text/connectors together, and an original-preserving SVG import/normalization operation with derivation receipts. These should remain bounded authoring operations; automatic summarization, invented connectors and automatic font shrinking are not acceptable substitutes for semantic design.

## Friction repaired in the current repository

The brief field is a project-relative file path, as specified by the existing schema. Documentation now agrees and long inline text, punctuation/path failures and multiline values produce contextual errors. Zone roles `slide-title`, `eyebrow`, `source` and `nav` render through the frame. Other role strings remain extensible but require explicit node bindings; an unbound `role: title` now fails at load instead of silently losing the headline. Frozen semantic runtime v4 and locked deliverables were not replaced.

No proposed API above has been implemented by this report. Existing low-level import/search/scaffold/edit/measure operations should be reused; migration-specific Python helpers can be archived once their source evidence and final delivery dependency closures have been retained.
