Give your agent a clear slide revision brief.

Copy a prompt, replace the bracketed details, and ask your agent to work in the deck’s YAML project. Keep the slide’s purpose, facts and visual structure together.

The prompt recipe

Seven details make revisions easier.

1. Project pathThe folder containing the deck source and lock, for example C:\Work\Client deck.
2. Stable slide IDUse an ID such as next-phase. Slide numbers change when you reorder the deck.
3. IntentWhat should the reader understand or decide after seeing this page?
4. Exact copyProvide replacement words, or say which wording the agent may rewrite.
5. EvidenceName the source file and page, cell or section supporting the claim.
6. ConstraintsKeep the template, preserve dates, stay at a density tier, or compare alternatives.
7. Definition of doneSource changed, checks passed, new build made, visuals reviewed, unresolved issues named.

Give the agent access to the project folder. These prompts assume a file-capable coding agent with the installed west-monroe-presentations skill and pptxgengo CLI. This HTML page documents the workflow; it does not run the CLI or connect to an agent.

Agree on material decisions. The agent can make routine copy and layout repairs under your instruction. Changes to the argument, commercial commitments, material claims or required evidence need your decision. Missing facts should become questions or visible placeholders.

Only have a PowerPoint file? Start with the existing-deck guide. A standalone PPTX is inventoried and rebuilt into a source project; migration does not automatically convert it to YAML.

10 prompts

01 · Resume

Find the slide you want to change.

Use this when you are returning to a project or are unsure which slide ID matches the page you see.

Use the west-monroe-presentations skill to resume this deck project:
[C:\Work\Client deck]

Run project status before drafting. List slides in order with their stable IDs, titles, templates, hidden state and review status. Tell me the current build and any toolchain drift, stale reviews or unresolved blockers.

I want to work on the page about [topic / current slide number]. Identify its stable ID and source file. Summarize its purpose, visible copy and evidence. Keep the existing deck unchanged while making this inventory. Give me a short recommendation for the next edit.

Use the ID from this inventory in the prompts below. PowerPoint page numbers are useful for locating a page, but are not durable identifiers.

02 · Copy revision

Revise one slide while preserving its facts.

For a bounded edit to an existing stock layout.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
Revise stable slide ID: [next-phase].

Reader and intent: [The sponsor should understand why we recommend this next phase.]
Replacement headline: [Exact wording here.]
Replacement body / bullets: [Exact wording, grouped by the existing content fields.]
Evidence: [File path and page / cell / section.]

Preserve the stock template, facts, numbers, dates, sources, owners, caveats and commitments. Keep each existing content key and array item count unless we explicitly agree to a different layout. Write in the West Monroe voice. If a claim is unsupported, flag it instead of inventing support.

Edit the slide source, update its composition-log entry, check and build the project, and measure the changed slide from the new layout report. Review its new appearance; report what was visually reviewed and what remains pending. If exact copy will not fit, explain the bounded options before dropping content.

A patch replaces each supplied field completely; arrays do not merge. Changing the number of bullets or cards may require another template contract.

03 · Template selection

Find a layout that matches the slide’s job.

Ask the agent to reason about relationships—comparison, sequence, heat map, interview list or economics—not simply text length.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
Reconsider the layout for stable slide ID [modernization-economics].
Its job is [show the economics of modernization and the mechanisms behind lower costs].
Preserve these content relationships and facts: [list them].
Source: [original deck path and source slide number].

Search the installed template index semantically for the content's purpose and structure. Inspect template contracts and open verified specimen screenshots. Bring me 2–3 plausible stock candidates, explaining what each preserves and what content reshaping it needs. Compare them with our actual copy; stock previews alone do not prove fit.

Build variations when useful, and log candidates, chosen template, reasons and source-slide mapping in composition-log.yaml. Preserve the original narrative unit: do not split one slide into multiple generic slides simply to make text fit. Aim for stock-template reuse; report a genuine library gap before using a custom composition.

Do not silently drop unmapped fields during a swap. Show me any material content tradeoff. Check, build, measure and visually review the selected result.

The skill aims for roughly 80% stock reuse on substantive pages. A template match is a starting point, not approval of new copy.

04 · Wordier copy

Use a consistent slide density.

Density changes typography across the slide body. It does not resize cards or move the boundary under the title.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
The copy on stable slide ID [four-pillars] needs more room.
Required copy and evidence: [provide both].

Inspect the pinned source, template contract and source-owned density ceiling. If the project needs an upgrade, propose and dry-run the migration before applying it.

Try slide-level density: compact, with header_density: comfortable. For this slide set auto_density: false so the chosen tier is deliberate. Keep corresponding body roles consistent across every card, list and table. Follow the source role scales; do not shrink one card independently, override the ceiling, change geometry, or remove essential facts to suppress an error.

If Compact does not fit, show me the options: tighten wording, use Dense if the template permits it, or choose a better stock layout. Explain readability tradeoffs. Keep the header Comfortable unless we explicitly choose another header tier, and respect the frame's title-line allowance.

Edit density metadata directly in the slide YAML, rebuild, inspect the layout report and visually review the changed page. Report the requested and effective tiers and any warnings.

V11 automatic fitting is enabled by default and can step the whole body down to Compact or Dense without rewriting YAML. To allow it, replace the prompt’s auto_density: false instruction with “keep automatic fitting enabled and report every adjustment.” Some agenda and lead-question templates permit Comfortable only.

05 · Sections

Add a section and a visible divider.

A PowerPoint section groups pages; a divider is a separate visible slide. Ask for both if you want both.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].

List the current sections. Add a section with ID [recommendations], title [Recommendations], beginning before stable slide ID [next-phase]. Also insert a stock divider slide at that boundary.

Inspect suitable divider templates and use [preferred stock divider key, or choose one that fits]. Use [approved image / registered photo ID] only if that divider requires an image. If the tester package lacks its original photo, report that and use an approved available asset or another stock divider.

Preserve existing slide order and content. Log the divider's composition choice, check and build the project, and review the divider plus the adjoining pages. Tell me the new section and divider IDs. Do not rename existing slide IDs.

Renaming a section changes its name; it does not rewrite the visible divider copy. Removing a section keeps its slides.

06 · Internal coordination

Add draft notes without rebuilding the template.

The workflow status, displayed label and tab color are independent. These notes belong to the slide source, outside content bindings and speaker notes.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
Add or update draft_review for stable slide ID [next-phase]:
  status: wip
  status_text: Work in progress
  status_color: brand.blue
  owner: [colleague name]
  due: '[authored date text]'
  updated: '[authored date text]'
  notes: |
    [Specific internal review task.]
    [Evidence or decision still needed.]
  placement: edge

Keep the shared template unchanged. Use the slide-owned Draft Review Note support. Rebuild and inspect the note in PowerPoint's editing view: the status tab is on the top-right slide edge, while the rest of the card sits off-slide. PDFs and PNGs crop away the off-slide card and are insufficient to review its text.

Keep these notes internal. For eventual client delivery, use the client export so the complete review group and its private metadata are removed from the packaged PowerPoint.

Use placement: pasteboard to put the entire card off-slide. Allowed workflow statuses: notstarted, wip, complete, qa. Colors: kpi.off, kpi.risk, kpi.on, brand.blue. Custom labels/colors survive status changes until explicitly cleared.

07 · Hand-edited PowerPoint

Bring manual changes back into the source.

There is no automatic round trip from an edited PPTX into the YAML project.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
Someone manually edited this PowerPoint: [C:\Work\Client deck edited by colleague.pptx].
The generated baseline it came from is [build ID / file path].

Preserve both files and do not overwrite the hand-edited deck. Inventory the edited PPTX, compare it with the source and baseline, and identify copy, structure and visual changes. Record who changed what in project.md. Ask me about ambiguous differences or changes to claims and commitments.

If this installation includes project reconcile, read docs/text-reconciliation.md and create a new review packet with project reconcile propose --project PATH --edited FILE --out NEW_DIRECTORY. Review baseline/current YAML/edited native copy, conflicts and every manual item. Adopt only explicit decisions naming the real reviewer, report hash, supported proposal IDs and reasons via project reconcile adopt --project PATH --packet DIRECTORY --decisions FILE. Stable v4.1.0 lacks these commands and older baselines lack the required lineage. For those or unsupported fields, manually reconcile approved changes into the slide YAML and composition log. Preserve unsupported styling and structure as unresolved review items. If someone modified the immutable build baseline itself, report the integrity blocker and resolve it through the supported workflow; do not bypass it or delete the lock.

Create a new build from reconciled source, compare it visually with the edited deck, and report any manual styling that cannot be reproduced by the selected stock template.

08 · Visual repair

Review the actual output and iterate.

Passing a layout check and looking at a source specimen are separate from reviewing the built slide.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
Review changed slide IDs [list IDs] and any neighboring pages affected by the change.

Finish source edits, then run project check, build and measure against the new layout-report.json. Use the current build's deck for review. Windows native rendering is experimental and has not been qualified on this machine: run render-doctor and attempt PDF/PNG export through installed desktop PowerPoint in the signed-in user session.

Inspect each changed page at full size for title wrapping, clipped bullets, vertical centering, overlapping labels, diagram relationships, font substitution and readability. Repair the source, rebuild, rerender and repeat until issues are resolved or clearly reported.

If native render fails, read render-error.txt and the PowerPoint window. Report the specific blocker; do not change global security policy or retry repeatedly. Use manual PowerPoint visual review/export as a fallback and label it honestly. Manual export does not create a signed CLI render receipt.

Attach valid CLI renders with genuine review decisions. Record agent checks as reviewed or issues_found; accepted is reserved for my actual acceptance. Report compiler checks, native rendering, visual review and unresolved issues separately.

Source or context changes make existing review stale. Do the final build, render and review after finishing the composition log. Windows needs desktop PowerPoint and the bundled IBM Plex fonts; reopen PowerPoint after font installation.

09 · Independent review

Check what the audience can understand.

A fresh reviewer gets an audience-safe packet, not the author’s hidden rationale.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
Audience: [role, prior knowledge, priorities].
Delivery: [emailed deck / live presentation].

Create a current content or finished-deck reviewer packet with --audience, whichever stage is ready. For a finished-deck packet, use the current rendered pages; if signed native rendering is blocked, assemble audience context and manually exported pages and disclose that fallback.

Ask a fresh agent with no authoring conversation to use only this packet. Have it state the argument and requested action, then identify unclear relationships, unsupported jumps, confusing visuals and excessive reading effort by slide ID / page. An emailed deck must explain itself without hidden notes.

Run source verification separately using the sources and claim ledger. Assess every finding, record the decision, make bounded repairs, and bring material argument or commitment changes to me. If an independent agent is unavailable, clearly label the exercise self-review.

10 · Handoff

Produce clean client and maintainer packages.

Deliver the cleaned client package and keep a source package for future edits.

Use the west-monroe-presentations skill. Project: [C:\Work\Client deck].
Prepare final handoff from the current build after all agreed edits.

Check the project, source accuracy and review state. Tell me which slides are rendered, reviewed, accepted or still pending. Do not mark pages accepted on my behalf. Confirm facts, commitments, caveats and sources are preserved.

Create separate new exports using project export: one --mode client ZIP and one --mode maintainer ZIP. Client export must remove the entire Draft Review Note group, including its visible status tab and private metadata. A cropped PDF alone does not sanitize the draft PPTX. Keep the source project and its immutable builds intact.

Give me the paths to both packages, the final deck's build ID, a short change summary and any unresolved review or Windows qualification limitations. If something blocks an export, name it and provide only the artifacts that are actually ready.

Ask for evidence of completion.

  • What changed? Stable slide IDs, source files and the reason for each material change.
  • What passed? Project validation, build and fit measurements, with the new build ID.
  • What was seen? Native or manual PowerPoint review, actual pages inspected and repairs made.
  • What remains? Missing evidence, operator decisions, render blockers and pending acceptance.

These guides are standalone and work offline. Copy buttons use the browser clipboard when available and a local selection fallback otherwise. If copying is blocked, select the prompt text and press Ctrl+C.
