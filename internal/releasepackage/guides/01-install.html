Windows tester guide

Install once. Start with a safe test.

The ZIP gives you the command-line tools, West Monroe template library and an agent skill. Install them for your Windows account, check the starter deck, then move on to your own work.

No Go or PythonNo administrator rights649 template definitionsOffline guide

This is a Windows preview. The binaries were cross-compiled and automated checks passed. Actual Windows execution and native PowerPoint export have not yet been qualified on a real Windows PC. Your smoke-test results help close that gap. The template source previews were reviewed on macOS; review every deck you build on Windows.

1

Choose your ZIP and extract it

Recommended first test

Tester ZIP · about 254 MB

Includes the tools, skill, SQLite search index, all template definitions, gallery previews, logos, icons, core artwork and fonts.

Original photo files are omitted. Photo metadata and gallery thumbnails remain searchable, but embedding those photos requires the full package or access to the original branding collection.

For photo-based slides

Full ZIP · about 4 GB

Includes everything in the tester package plus the original photography. Choose this if you will build slides that use those photos.

Allow room for both the extracted folder and the installed copy. Installation keeps the extracted source folder.

  1. Save the ZIP to a local folder, then use Extract All in File Explorer.
  2. Open the extracted pptxgengo-windows-amd64 folder. You should see install-windows.ps1, smoke-test-windows.ps1 and bin.
  3. Use the package matching your PC: amd64 means Windows x64; ARM64 uses a separate package. Check Settings → System → About → System type if unsure.

Do not run the installer from inside the ZIP. This guide works by double-clicking its HTML file; the toolkit itself runs from PowerShell.

This handoff is 0.1.0-local.21-windows-preview.1. The supplied x64 files are pptxgengo-windows-amd64-tester-20261006.zip and pptxgengo-windows-amd64-full-20261006.zip.

2

Open PowerShell and install

In the extracted package folder, click the File Explorer address bar, type powershell and press Enter. This opens PowerShell in the right folder. Run:

PowerShell · extracted package folder
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1

The installer checks file hashes before copying the package. It then:

  • Installs into %LOCALAPPDATA%\pptxgengo\releases\VERSION.
  • Adds that release’s bin folder to your user PATH.
  • Installs west-monroe-presentations into %USERPROFILE%\.codex\skills, or into CODEX_HOME\skills when that variable is set. An existing skill is preserved in a timestamped backup.
  • Installs bundled IBM Plex Sans and IBM Plex Mono fonts for your user account.

Restart PowerPoint, Codex and your terminal afterward. PowerPoint needs a restart to see newly installed fonts; Codex needs a restart to load the skill.

The installer adds a skill to an existing Codex installation; it does not install Codex itself. This package does not provide a ChatGPT app skill installer. -ExecutionPolicy Bypass applies to this PowerShell process; it does not change the machine’s execution policy. Enterprise controls may still block the script or binaries.

3

Check the CLI and browse the library

Open a new PowerShell window and run:

PowerShell · new terminal
pptxgengo --version
pptxgengo paths
pptxgengo catalog --open

You should see a version, resolved package paths and the template gallery in your browser. The gallery opens directly from the installed files; it does not need a running server.

You can also run .\bin\pptxgengo.exe --version from the extracted folder. This works without relying on PATH and is useful when troubleshooting.

Open the design documentation and galleries

The toolkit includes two ways to browse the design system. Both are local to your computer and work without internet access.

Design-system documentation site

For foundations, primitives, components, composites, frames and searchable template documentation, run this in PowerShell:

PowerShell · keep this window open
pptxgengo docs
  1. Leave that PowerShell window open while browsing. The command runs a local server and will not return to the prompt until you stop it.
  2. Open Edge or Chrome and type http://localhost:8787/ into the address bar. The CLI prints the actual address; it does not automatically open the browser.
  3. Use another PowerShell window for deck commands. When finished browsing, press Ctrl+C in the server window to stop it.

If port 8787 is already in use, run pptxgengo docs --addr localhost:8790 and browse http://localhost:8790/. For portable use, run .\bin\pptxgengo.exe docs from the extracted package folder.

Template specimen and asset galleries

These commands open the gallery pages in your default browser:

PowerShell · no server needed
pptxgengo catalog --design-system --open
pptxgengo catalog --assets --open

The template gallery shows native-reviewed source specimens. The asset gallery browses photos, icons and artwork. Documentation explains how the design system works; neither documentation examples nor specimen previews prove that your replacement copy fits. Build and review your actual slides.

If browser opening fails, run pptxgengo catalog --design-system --print to get the HTML file path, then open that file manually. The HTML guides you are reading are separate standalone files and need no server.

4

Run the starter smoke test

Return to PowerShell in the extracted package folder and run the core test first. It uses bundled sample content and creates a new project; you do not need to supply a client deck.

PowerShell · extracted package folder
powershell -NoProfile -ExecutionPolicy Bypass -File .\smoke-test-windows.ps1

The test searches the SQLite library, checks a preview, initializes and splits a two-slide project, adds a slide section, builds the PowerPoint, checks measurements, runs a migration dry-run and creates a client ZIP.

Keep the results folder. The script prints its location, normally under %TEMP%\pptxgengo Windows smoke …. It contains summary.json, command output, error logs and the generated project. Send that folder to the maintainer if a step fails.

Want a predictable location? Add -Out 'C:\Work\pptxgengo-smoke-1'. That folder must not already exist. Use sample content for the first test; do not put confidential client content in a troubleshooting bundle.

Optional: test native PowerPoint export

After the core test passes, restart PowerPoint and make sure desktop Microsoft PowerPoint is installed and activated. Run this from a signed-in Windows desktop session:

PowerShell · desktop PowerPoint required
powershell -NoProfile -ExecutionPolicy Bypass -File .\smoke-test-windows.ps1 -Native

This reruns the core test, checks actual PowerPoint file access and fonts, exports PDF and slide PNGs, makes a contact sheet and attaches a signed render receipt to the sample project. The native backend needs Windows PowerShell 5.1, the bundled fonts and NTFS storage. It operates on its task copy and closes only that copy.

Export success is not visual approval. Open the generated PPTX and inspect every full-size PNG. Look for substituted fonts, clipped or overlapping text and unexpected line breaks. A native test failure can leave the core test marked passed in summary.json.

If something does not work

Start with the message and the smoke-test logs. Resolve the reported issue before retrying.

“pptxgengo is not recognized”

Close the terminal and open a new one so it reads the updated user PATH. From the extracted folder, try .\bin\pptxgengo.exe --version. If that works, the executable is available and the remaining issue is PATH. Use the installed path printed by the installer if you need to run it directly.

The script or executable is blocked by company policy

The preview contains unsigned binaries. Enterprise application controls can block them, and group policy can override a process-level PowerShell option. Record the exact message and ask IT or the maintainer for the approved route. Do not disable security controls or change global execution policy.

“Destination already exists” during installation

Existing release folders are deliberately preserved. If the earlier installation works, use it. To install another copy, supply a new destination:

PowerShell · choose a new folder
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1 -Destination "$env:LOCALAPPDATA\pptxgengo\releases\windows-preview-test-2"

Choose a folder that does not already exist; do not delete a working release just to rerun the installer.

Windows cannot run the executable

Check your PC’s system type against the package folder name. The supplied amd64 package targets x64; an ARM64 build is separate. A blocked or quarantined executable can look similar to an architecture problem. Keep the exact Windows error and confirm the package came from the maintainer.

Font installation warned, or slides look different

Core installation can succeed even when font installation warns. Find the bundled .ttf files in library\wm-design-system\v11\fonts, select them in File Explorer and install for your user account if company policy allows. Restart PowerPoint afterward. Native review requires IBM Plex Sans and IBM Plex Mono; do not accept a substituted-font render as final.

Native export fails or PowerPoint shows a prompt

Check desktop PowerPoint activation, the PowerPoint window and the failed command’s error log. For a render failure, inspect render-error.txt in the render output folder when present. Pending prompts, Protected View, missing fonts or company policy can block COM automation. Address the specific cause rather than repeatedly retrying or changing global Protected View settings.

You can still open the generated PPTX and export PDF or images manually to review it. Manual export does not create the CLI’s signed native receipt. Windows does not use the macOS “Grant File Access” workflow.

A selected photo cannot be found

The tester ZIP intentionally omits original photos. Use the full ZIP, or point WMDS_BRANDING_ROOT to the matching original branding collection supplied by the maintainer. Thumbnails in the gallery show what is available; they are not the original image files for embedding.

I prefer portable use or want to skip an install step

You can run .\bin\pptxgengo.exe directly from the extracted folder without installation. Fonts and the agent skill still need to be available for their respective workflows. Installer switches -SkipSkill, -SkipFonts and -NoPath skip those steps individually. Portable use does not resolve missing fonts or enterprise policy restrictions.
